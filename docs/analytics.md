# Аналітика points.gs

Спільне підключення — `js/analytics.js`, GA4 Measurement ID — `G-RSXV2Q3WG2`. Воно використовується на актуальних англійських та українських сторінках. HTML-фрагменти, шаблони та сторінки-перенаправлення окремих переглядів не надсилають.

Код набуде чинності після звичайного релізу GitHub Pages. Налаштування кабінетів GA4, CookieYes і Search Console та надходження даних на робочому сайті треба перевірити окремо.

## Що вимірюється

| Подія | Коли надсилається | Як читати результат |
| --- | --- | --- |
| `play_store_click` | Натискання посилання Google Play | Намір перейти до гри; `link_location` показує місце кнопки. Це не встановлення. |
| `article_read` | Після згоди відвідувач досяг 90% вмісту статті й провів у ній щонайменше 30 активних секунд | Ознака залученого читання, один раз за відкриття статті. Час рахується лише у видимій вкладці з фокусом, поки текст статті хоча б частково є у вікні перегляду. |
| `share` | Успішне копіювання посилання або успішне завершення системного меню поширення | `method`, `content_id`, `content_type=article`; скасування системного меню не рахується. |
| `share_click` | Натискання посилання поширення статті в соцмережі | Намір поширити; `method` — мережа, `content_id` — канонічний шлях статті, `content_type=article`. |
| `social_click` | Натискання посилання профілю студії або гри в соцмережі | Намір перейти до профілю; параметр `network`. |
| `press_asset_download` | Натискання посилання завантаження пресматеріалу | `asset_type`, `file_name`, `link_location`. Подія фіксує клік, а не підтверджує завантаження файлу. |
| `generate_lead` | Formspree підтвердив успішне надсилання контактної форми | Успішне звернення; `form_id` розрізняє форми. |
| `contact_error` | Помилка надсилання контактної форми | Невдала спроба; параметр `form_id`. Текст повідомлення відвідувача не передається. |
| `contact_click` | Натискання `mailto:` | Намір написати листа; `link_location` показує місце посилання. Це не підтвердження надсилання листа. |

Натискання соціальних посилань вимірює намір перейти або поширити. Відкриття вікна соцмережі не підтверджує публікацію.

Власні події містять `page_language`, `page_type`, а на статтях — `article_id`. Для стандартного URL сторінки використовуйте готові виміри GA4, наприклад Page path. Контролер очищує налаштовані `page_location` і `page_referrer` від фрагментів і довільних параметрів; у `page_location` зберігаються стандартні UTM для атрибуції. Обмеження параметрів наших власних подій не поширюється на автоматичні події Enhanced measurement: вони можуть самостійно передавати повні `link_url`, пошукові та формові параметри.

## Згода CookieYes

Використовується наявний банер CookieYes із ID `e6ba3bfedc57c067fa59e14b`. Google tag завантажується лише після згоди на категорію **Analytics**. До згоди події не накопичуються для пізнішого надсилання. Відкликання згоди припиняє надсилання наступних подій.

Перевірте у кабінеті CookieYes, що цей банер належить points.gs, категорія Analytics доступна, а збережений вибір відвідувача коректно читається на обох мовних версіях.

У браузері банер уже перевірено на `https://points.gs/devlog.html`: він відкривається без помилок. На `localhost` CookieYes повідомляє про зміну URL, оскільки локальна адреса відрізняється від зареєстрованого домену. Локальні тести контролера імітують CMP; справжні прийняття, відмову та відкликання згоди слід перевірити на points.gs після релізу.

## Один раз налаштувати у GA4

1. Виберіть ресурс із вебпотоком `G-RSXV2Q3WG2`.
2. Після перевірки подій відкрийте **Admin → Data display → Events**. У Recent events позначте зірочкою `play_store_click` і `generate_lead` як ключові події. `press_asset_download` можна додати, якщо пресматеріали — окрема ціль. Для загальної оцінки залучення достатньо звичайного звіту `article_read`. [Інструкція Google](https://support.google.com/analytics/answer/13128484?hl=en).
3. Не створюйте ще один `generate_lead` з автоматичного `form_submit`: код уже надсилає його після успіху Formspree. Не позначайте одночасно `form_submit` і `generate_lead` як одну й ту саму бізнес-ціль.
4. У **Admin → Data streams → вебпотік → Enhanced measurement → налаштування** перевірте автоматичні вимірювання. Щоб збирати лише описані тут контрольовані події дій, вимкніть **Outbound clicks**, **File downloads**, **Site search** і **Form interactions**. Це також прибере дублікати кліків і автоматичний збір їхніх повних адрес, пошукових та формових параметрів. Ці налаштування кабінету ще не змінено: входу до GA4 у межах цієї роботи не було. [Автоматичні події](https://support.google.com/analytics/answer/9216061?hl=en).
5. В **Admin → Data display → Custom definitions → Create custom dimensions** створіть потрібні виміри зі **Scope: Event** і точними назвами параметрів із таблиці нижче. Зберігайте їх до накопичення робочих даних; у звітах вони можуть з'явитися через 24–48 годин. [Інструкція Google](https://support.google.com/analytics/answer/14239696?hl=en).

| Назва виміру | Event parameter | Для чого |
| --- | --- | --- |
| Page language | `page_language` | Порівняння мов |
| Page type | `page_type` | Головна, статті, Press Kit та інші типи сторінок |
| Article ID | `article_id` | Порівняння статей між мовними версіями |
| Link location | `link_location` | Порівняння кнопок і місць посилань |
| Asset type | `asset_type` | Архів, відео, зображення |
| Form ID | `form_id` | Порівняння контактних форм |
| Network | `network` | Порівняння переходів до соціальних профілів |

`file_name`, `method`, `content_id` і `content_type` можуть мати готові виміри GA4. Спочатку перевірте їх у ресурсі; власний вимір додавайте лише якщо потрібного немає. Не створюйте власні виміри для повних URL або вмісту форм.

Якщо автоматичні вимірювання залишені ввімкненими, Enhanced measurement може паралельно збирати `click` і `file_download`. Для цілей цього сайту використовуйте `play_store_click` та `press_asset_download`; додавання їх до автоматичних подій завищить кількість однакових дій. `send_page_view: false` у контролері керує початковим автоматичним переглядом, але не вимикає вимірювання змін історії браузера в Enhanced measurement; сайт зараз використовує звичайну навігацію між HTML-сторінками.

Для порівняння джерел відкрийте **Reports → Acquisition → Traffic acquisition** і виберіть потрібну ключову подію. В Explore можна зіставити `article_id` або `link_location` з кількістю відповідної події.

## UTM для публікацій

Мітки додаються до посилань **із зовнішніх публікацій на сайт**. Усі значення — малими латинськими літерами, слова через `_`:

- `utm_source`: платформа, наприклад `tiktok`, `youtube`, `x`.
- `utm_medium`: `social` для звичайних дописів; `paid_social` для оплаченої реклами.
- `utm_campaign`: одна назва кампанії на всіх платформах, наприклад `halloween_2026`.
- `utm_content`: конкретний ролик, допис або місце посилання, наприклад `cauldron_video` чи `profile_bio`.

Приклади готових посилань:

```text
https://points.gs/?utm_source=tiktok&utm_medium=social&utm_campaign=halloween_2026&utm_content=profile_bio
https://points.gs/?utm_source=youtube&utm_medium=social&utm_campaign=halloween_2026&utm_content=gameplay_description
https://points.gs/uk/pillar_1.html?utm_source=x&utm_medium=social&utm_campaign=halloween_2026&utm_content=announcement_uk
```

Для посилання на статтю замініть шлях перед `?`, зберігши мітки. **Не додавайте UTM до внутрішніх посилань сайту**: місце Play-кнопки вже передає `link_location`. [Мітки кампаній у GA4](https://support.google.com/analytics/answer/10917952?hl=en).

За цими даними можна зіставити джерело відвідування з кліком Google Play. Атрибуція встановлень потребує окремих даних застосунку / Play Console; сайт її не підтверджує.

## Search Console

Якщо points.gs уже підтверджений у Search Console, використовуйте наявний ресурс. Інакше додайте **Domain property: `points.gs`**, візьміть виданий саме вашому обліковому запису DNS-запис, додайте його у провайдера DNS та натисніть Verify. Значення підтвердження не можна вигадати; DNS-запис залиште після перевірки. [Підтвердження власності](https://support.google.com/webmasters/answer/9008080?hl=en).

У **Sitemaps** надішліть [наявну карту сайту](https://points.gs/sitemap.xml), якщо її ще немає у звіті. Перевіряйте статус обробки й **Performance → Search results** для запитів, сторінок, показів та кліків. [Надсилання sitemap](https://support.google.com/webmasters/answer/7451001?hl=en).

## Оновлення коду

Після змін контролера `js/analytics.js` або генерації статей виконайте з кореня репозиторію команди в цьому порядку, підставивши фактичну дату зміни:

```text
python tools/build_blog.py --modified-date YYYY-MM-DD
python tools/sync_analytics.py
```

Перша команда оновлює згенеровані статті, друга синхронізує аналітику та версії підключення. Після цього перевірте зміни й виконайте звичайний реліз GitHub Pages.

## Перевірка після релізу

1. У чистій сесії відхиліть Analytics у CookieYes. У Network не має бути запитів Google Analytics; кліки та читання не повинні з'являтися у Realtime.
2. Дозвольте Analytics. Перевірте один `page_view` і власні події в **Reports → Realtime**. Для параметрів відкрийте сайт із `?analytics_debug=1` та **Admin → Data display → DebugView**. Наприклад: `https://points.gs/?analytics_debug=1`. На `localhost` і `127.0.0.1` налагодження вмикається автоматично. Альтернатива — [Google Tag Assistant](https://tagassistant.google.com/). Не вмикайте debug mode для всіх відвідувачів. [DebugView](https://support.google.com/analytics/answer/7201382?hl=en).
3. Перевірте Play-кнопки, пресматеріали й копіювання посилання. Для `article_read` дочитайте до 90% і тримайте текст статті у видимій вкладці з фокусом щонайменше 30 секунд; час у шапці чи футері без видимого тексту статті не рахується. Повторне прокручування не має створювати другу подію.
4. Відкличте згоду через налаштування CookieYes. Наступні дії не повинні надсилатися. Дії, виконані до згоди, не мають з'являтися після її надання.
5. Повторіть основні дії на англійській та українській сторінках. Для `generate_lead` автоматичні перевірки мають підміняти відповідь Formspree; не надсилайте реальні звернення під час автоматизованих тестів.

Якщо даних немає, перевірте вибраний ресурс, згоду, блокувальники та Network. Відсутність подій після відмови від Analytics є очікуваною.
